Polyphone 内置了一个遵循 Model Context Protocol（MCP）的服务器。MCP 是一项标准，可让 AI 助手使用其他软件。
启用该服务器后，像 Claude 这样的助手就可以处理在 Polyphone 中打开的音色库：您用自己的话描述想要的效果，助手便会浏览音色库、编辑它们、使用 Polyphone 的工具，并测量结果。

每一处修改都会立即显示在编辑器中，并且可以撤销，就像您亲手修改的一样。
本教程介绍如何将 Claude 连接到 Polyphone，然后给出一些可以提出的请求示例，并附有音频文件供您试听结果。


## 助手能做什么 {#doc_principles}


助手可以访问 Polyphone 中打开的所有内容：

* **浏览**：音色库及其采样、乐器和预设，每个分区的参数，以及在[树状图](manual/soundfont-editor/tree.md)中选中的元素（因此它能理解“这个采样”或“选中的乐器”这样的说法），
* **编辑**：创建、重命名、复制或删除元素，修改参数、音符范围和力度范围、循环点、调制器……
* **工具**：[工具菜单](manual/soundfont-editor/tools/index.md)中的大部分工具，例如自动循环、音量调整、采样自动定位或自然释音，
* **声音分析**：测量响度、音高、泛音、起音、循环质量等，并渲染由合成器演奏的音符。

分析功能至关重要：**助手听不到声音**。
它会在修改前后测量声音，就像工程师读取频谱分析仪一样。
因此，它可以检查循环是否有咔嗒声、音符是否准确、整个键盘上的音量是否均匀——但最终的判断仍然取决于您的耳朵。

助手所做的每一处修改都是音色库历史记录中的一步：在 Polyphone 中按 :kbd:`Ctrl`+:kbd:`Z` 即可撤销。
在您要求助手保存音色库或自己保存之前，任何内容都不会写入磁盘。


## 设置 {#doc_setup}


### 在 Polyphone 中启用服务器


打开[设置](manual/settings.md#doc_ai_assistant)，进入 :guilabel:`AI助手` 部分。
勾选 :guilabel:`允许 AI 助手访问已打开的音色库`：下方的一行随即显示服务器地址，默认为 http://127.0.0.1:8642/mcp。
如果端口 8642 已被其他软件占用，请通过 :guilabel:`端口` 选择另一个端口。

服务器只接受来自您自己计算机的连接。
同一页面列出了提供给助手的所有功能，分为四类：:guilabel:`浏览`、:guilabel:`编辑`、:guilabel:`工具` 和 :guilabel:`声音分析`。


### 连接 Claude Code


<a href="https://claude.com/claude-code" target="_blank">Claude Code</a> 是 Anthropic 开发的一款在终端中运行的助手（也提供 VS Code 和 JetBrains 编辑器的扩展）。
安装后，使用 :guilabel:`复制` 按钮复制 Polyphone 设置中显示的命令，然后在终端中运行：

```
claude mcp add --transport http polyphone http://127.0.0.1:8642/mcp
```

默认情况下，只有从运行该命令的文件夹启动 Claude Code 时，它才会使用该服务器。
若要在任何文件夹中都能使用 Polyphone，请加上选项 `--scope user`：

```
claude mcp add --scope user --transport http polyphone http://127.0.0.1:8642/mcp
```

然后启动一个新的 Claude Code 会话：Polyphone 的功能在会话启动时加载，因此此时 Polyphone 必须已经打开并启用了服务器。
在 Claude Code 中使用命令 `/mcp` 可以查看服务器“polyphone”是否已连接。
当助手第一次想使用 Polyphone 的某个功能时，Claude Code 会请求您的许可，您可以选择以后不再就该功能询问。

**注意：** 其他通过 HTTP 传输支持 MCP 的助手也可以连接到同一地址。


### 最初的问题


先从简单的问题开始，看看助手如何浏览音色库：

* *“Polyphone 中打开了哪些音色库？”*
* *“这个音色库包含什么？有没有没被任何乐器使用的采样？”*
* *“列出所有预设，并附上它们的库编号和预设编号。”*

在 Polyphone 的树状图中选中一个元素后，助手就可以引用它：*“把选中采样的音量降低 6 分贝”* 或 *“给这些乐器的名称加上前缀‘Organ’”*。
对于小的修改，结果会立即显示在编辑器中。


## 示例：检查并修正乐器 {#doc_check}


用大量采样制作乐器时很容易出错，而且有些错误很难察觉：某个音符稍微走音，某个采样比相邻的采样稍响，某个循环要过几秒钟才出现咔嗒声……
助手可以在几秒钟内检查整个乐器。

如果想亲自试一试，请下载 <a href="files/flute-with-mistakes.sf2" download>flute-with-mistakes.sf2</a> 并在 Polyphone 中打开。
该文件包含一个长笛乐器，其中故意加入了几处错误。
请听从 C4 到 F6 的音阶，最后是一个长音 G6：

![](files/ai-assistant-flute-before.mp3)

然后提出请求：

*“检查乐器‘Flute’：有没有走音、太响或太轻的音符，没有声音的琴键，或者有问题的循环？”*

助手会分析该乐器（一个功能即可测量每个分区的响度、音高、音色和循环），然后详细检查可疑的采样。
它的回答列出了以下问题：

* 琴键 E4 没有声音：“Flute 63”的分区在 升D4 结束，而下一个分区从 F4 开始，
* “Flute 69”高了一个半音：它发出的是 A4（440 Hz），但其根音符是 升G4，
* “Flute 78”高了 30 音分：录音本身音准正确，但其校正值为 +30 音分，
* “Flute 84”的分区比其他分区响 6 分贝（琴键 B5 到 升C6），
* “Flute 90”的循环有咔嗒声：循环点处的波形不吻合，且循环长度不是周期的整数倍。

接着提出请求：*“修正这些问题。”*

助手会把“Flute 63”的音符范围扩展到 E4，将“Flute 69”的根音符设为 A4、“Flute 78”的校正值设为 0，为“Flute 84”的分区设置 6 分贝的衰减（采样本身不做修改），并对“Flute 90”使用[自动循环](manual/soundfont-editor/tools/sample-tools.md#doc_autoloop)工具。
重新分析确认了结果：没有无声的琴键，没有走音的音符，各处音量一致，循环点处的波形现在也已吻合。
修正后的同一音阶：

![](files/ai-assistant-flute-after.mp3)

助手会说明自己在做什么，而且常常需要做出选择：在这里，它衰减了一个分区，而没有修改采样的音频数据。
如果您更喜欢其他解决方案，直接说出来即可——您还可以在编辑器中查看每一处修改，或将其撤销。


## 示例：从零开始创建乐器 {#doc_create}


像 Claude Code 这样的助手还可以在您的计算机上运行程序，例如用来计算采样。
将这一能力与 Polyphone 的功能结合起来，就可以根据描述制作出完整的乐器。
上一个示例中的长笛就是这样制作的，起点是两条请求：

*“你能为琴键 60 做一个长笛的声音吗？”*

*“现在在一个新的音色库中，做一个有多个力度级别的完整长笛。”*

以下是助手一步步完成的工作：

1. 测量了一个 General MIDI 音色库中录制的长笛，以了解该乐器在各个音区的音色（泛音、气息噪声、起音、颤音），
2. 编写了一个合成 39 个采样的程序：从 C4 到 C7 的 13 个音符，每隔 3 个琴键一个，每个音符有三种力度——*p* 更暗、气息声更多、起音柔和，*f* 泛音更丰富、起音更清晰，
3. 将这些采样导入新的音色库，设置它们的根音符和循环，并为每种力度创建一个乐器，释音为 0.4 秒，
4. 将三个乐器叠放在一个预设中（库 0、预设 73，即 General MIDI 标准中的长笛），力度范围分别为 0-49、50-89 和 90-127，方法如教程“[使用多个力度层制作逼真的乐器](tutorials/realistic-instruments-with-multiple-velocity-layers.md)”所述，
5. 在每个力度边界的两侧渲染音符：音量只变化 0.1 到 0.4 分贝，因此从一个力度层到下一个力度层时，只有音色发生变化。

最后一步暴露了一个弱点：在最高的八度中，三个力度层的音色几乎相同。
助手修改了程序，使强奏的音符在高音区也变得更明亮，然后重新生成采样并重新制作了乐器。

请听用力度 35、70 和 110 弹奏的琴键 C4——每个力度层一个音符：

![](files/ai-assistant-flute-layers.mp3)

再听一段越来越响的乐句，音色随力度变化：

![](files/ai-assistant-flute-phrase.mp3)

合成的长笛永远比不上优秀的录音：这个示例展示的更多是方法，而不是声音本身。
对于您自己的录音，同样的请求也适用：*“导入这个文件夹中的 wav 文件，找出它们的根音符，为它们设置循环，并制作一个每种力度一个力度层的乐器。”*


## 更多想法 {#doc_ideas}


以下是其他效果很好的请求：

* *“为所有乐器设置自然释音，低音区更长。”*
* *“这个乐器的高音太亮了：从 C6 开始逐渐让它们柔和一些。”*
* *“以这个管风琴乐器为基础，创建一个 celeste 音栓，在 C4 处每秒 3 次拍频。”*
* *“把所有立体声采样转换为单声道，并更新乐器。”*
* *“比较这两个采样：为什么第二个听起来更闷？”*
* *“用简单的话解释这个预设的调制器。”*
* *“删除未使用的采样和重复的采样，然后将音色库保存为 sf3 格式。”*


## 提示 {#doc_tips}


* **明确范围**：“只修改乐器‘Piano’”、“不要改动采样，只改乐器”……
* **要求测量**：“检查结果”或“比较修改前后”会让助手用分析功能验证自己的工作。
* **大的修改要循序渐进**，并在各步之间试听。
* **保留副本**：保留一份音色库的副本，满意后再保存——可以让助手保存，也可以按 :kbd:`Ctrl`+:kbd:`S`。
* **大型音色库**的分析需要更长时间：与其分析整个音色库，不如针对某个乐器或预设。
* **隐私**：助手收到的是名称、参数、测量结果和波形图像，而不是音频本身；但这些数据和对话的其余部分一样，会被发送到助手的服务。
